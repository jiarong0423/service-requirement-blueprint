Post-build reference

Service Requirement Blueprint

A local English-only proof of concept that helps one client and one contractor turn requirements into a fixed agreement, record delivery and explicit acceptance, and export verifiable evidence without exposing private drafts.

Functional source: responsive implementation commit e7b7306; this offline map was added in c182197. Later 6-ship commits update documentation, licensing, and release evidence without changing the mapped delivery workflow.

One real action: submit and review a delivery

Three-stop reference route

Inputapp/routes/localized.py

Search for delivery_submit. This POST boundary reads form data and passes server-owned identity to the workflow.

Rules and storageapp/services/delivery_workflow.py

Search for submit_delivery. This validates the formal case, exact criteria, idempotency, version cap, database transaction, and fixed record.

Output and proofapp/templates/delivery_dashboard.html

Search for page.delivery_history. The page renders prior versions without rewriting them. The end-to-end proof starts at test_return_remediation_reinspection_acceptance_and_export.

Main pieces

  • Routes: app/routes/localized.py owns HTTP methods, CSRF boundaries, protected downloads, and English URLs.
  • Workflow services: app/services/ owns permission checks, transactions, immutable versions, candidate/formal evidence, delivery, and export verification.
  • Database: migrations/ defines append-only rows and transition guards in local SQLite.
  • Controlled files: the runtime instance stores exact JSON, PDF, SVG, delivery, and evidence ZIP bytes outside Git.
  • Presentation: app/templates/, app/static/css/app.css, and app/i18n/catalog.en.json render the English interface without owning business authority.

To change this, start here

  • System wording: edit the existing key in app/i18n/catalog.en.json, then run the i18n contract tests.
  • Delivery page layout: start at app/templates/delivery_dashboard.html and app/static/css/app.css.
  • Delivery or acceptance rules: start at app/services/delivery_workflow.py and confirm the database guard in migrations/006_slice7_delivery.sql.
  • Evidence ZIP contents: start at app/services/evidence_export.py and app/schemas/evidence-export-manifest.v1.schema.json.
  • HTTP behavior: start at the named route in app/routes/localized.py; keep role and state decisions in the service layer.

A practice to reuse

The narrow-table issue showed why an observable stop condition matters. “Make the table responsive” became measurable evidence: at a 789 CSS-pixel viewport, the body must not overflow, the table must scroll inside its labeled region, and ordinary English words must remain readable.

The implementation is anchored at table-scroll in app/templates/delivery_dashboard.html and the sizing rules in app/static/css/app.css. The regression guard is test_delivery_history_uses_accessible_responsive_table_region in tests/test_slice7_delivery.py.

On another project, use the same pattern: turn a visual complaint into a viewport, a measurable container boundary, and one automated contract before calling the repair complete.

Run it again

From the repository root, set the three documented demo-password environment variables with a no-echo mechanism, then initialize a new local demonstration instance only when one does not already exist:

export DEMO_OWNER_PASSWORD DEMO_CONTRACTOR_PASSWORD DEMO_ADMIN_PASSWORD
.venv/bin/python -m app.cli init-demo
POC_LOCAL_HTTP=1 .venv/bin/python -m app

Open http://127.0.0.1:5000/. The server is loopback-only. Generated accounts and case artifacts stay in the ignored local instance directory.

Offline reference only. No analytics, remote assets, embedded credentials, or network dependency.
